# Monitor v2 — Hardware Sensors, Layout Polish, CI

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Add LibreHardwareMonitor-backed CPU/board sensors with a portable first-run setup flow, a clearer default layout, auto-width, fixed-size Monitor button, and per-model loading/running cards; then add GitHub Actions CI.

**Architecture:** A new `monitor_lhm` module probes/parses LHM's `data.json` (matched by `HardwareId`/`SensorId`, never by machine names). The sampler merges those values into the existing `Sample`. The Settings tab gains a "Hardware sensors" section that owns discovery, download, locate and start. Layout/UX fixes land in `monitor_panel` and the manager.

**Tech Stack:** Rust 1.100, eframe 0.37, ureq 3 (rustls), serde_json, `windows` 0.62, `tar.exe` for zip extraction (built into Windows 10+).

**Spec:** `docs/superpowers/specs/2026-11-14-monitor-config-design.md` plus the requirement list in this plan.

## Requirements captured (from the user, verbatim intent)

- Monitor button: fixed size across "Monitor" / "Monitor on" / "Close"; no resize on hover.
- Model cards: yellow border while a model is loading, green while it is serving.
- Overlay: optional title, custom text, so the panel identifies itself.
- Clear labels: no "VRAM IO"; uptime, power and PEAK must be obvious.
- Auto width option so no row wraps.
- Temperatures split by source: GPU, CPU, board, plus GPU hotspot / memory junction.
- CPU energy: watts.
- Default rows: model info / GPU / fan / CPU / RAM+board.
- Hardware sensors must work on any machine, not just this one.
- Setup flow: switch → if the tool is missing, ask Download / Locate / Cancel; download instructs about the admin prompt; switches appear once connected.
- CI that builds on every push.

## Global Constraints

- Windows only; no new runtime dependency other than `zip`-free extraction via `tar.exe`.
- Never block the UI thread: LHM fetch runs in the sampler thread, never in `ui()`.
- A missing/unreachable LHM must degrade to `--`, never crash or hide the rest.
- Portability: match sensors by `HardwareId` prefix (`/intelcpu`, `/amdcpu`, `/nvidiagpu`, `/atigpu`, `/lpc`) and `SensorId` suffix, never by hardware display names.
- Existing settings files must keep working: migrate `temp` → `gpu_temp`, `gpu_mem` → `vram_bus` on load.
- All Windows calls keep using `CREATE_NO_WINDOW` where applicable; elevation only via `ShellExecuteW("runas")`.
- 32 tests currently pass; the suite must stay green.

## File Structure
